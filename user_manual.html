User Manual and Reference Guide

A plain-language guide to every tab, section, control and result in the laboratory. It is written for a student who has only basic knowledge of machine learning: every model is explained from the beginning, then the screen is explained piece by piece.

1 · About the system

The Technical AI Model Laboratory is an interactive teaching application. It lets you experiment with five ideas from machine learning, all set in one realistic scenario: looking after technical equipment such as a radio, a controller or a communication unit. You move sliders, type sentences and choose options, and the application shows you immediately what each model does and why.

Important

Everything in the laboratory uses small, synthetic (artificially created) data. The documents are invented, the sensor readings are generated by a random-number program, and the probabilities are hand-written teaching values. The laboratory demonstrates how the methods work. It is not a validated tool for judging whether real equipment is safe.

3 · Basic ideas you need first

This section explains the handful of words used throughout the laboratory. Section 13 is a longer glossary.

Machine learning
Instead of writing exact rules (“if the temperature is above 70, raise an alarm”), we give a program many examples and let it find the pattern itself.
Model
The result of that learning: a mathematical recipe that turns an input (a sentence, a set of readings) into an output (a category, a score).
Features
The measurable properties a model looks at. For the VAE the features are four readings: temperature, vibration, voltage and packet loss. For text models the features are words.
Training and inference
Training is the learning phase, when the model studies examples. Inference is the using phase, when the trained model is given something new. In the laboratory, training happens once when the program starts; inference happens every time you move a slider or press a button.
Supervised and unsupervised learning
With supervised learning every training example comes with the right answer (a label). Naive Bayes is trained this way: each training phrase has a category. With unsupervised learning there are no labels. The VAE is trained this way: it only ever sees normal readings and learns what “normal” looks like.
Probability
A number between 0 and 1 (or 0% and 100%) saying how likely something is. All probabilities for one question add up to 1.
Anomaly
An input that is unusual compared with what the model has seen. “Unusual” does not automatically mean “dangerous”.
Retrieval
Searching a collection of documents and returning the most relevant ones, ranked by a score.
Ground truth and evaluation
Ground truth is the set of known correct answers prepared by a person. Evaluation compares a system’s output with it using numbers (metrics) so that two systems can be compared fairly.
Synthetic data
Data created by a program or written by hand for teaching, rather than collected from real equipment.
Why so small?

The datasets are kept tiny on purpose, so you can see every number and follow the reasoning. Real systems use far more data, and their results would be much less easy to read.

The application is built so that every change you make re-runs the page from top to bottom. This is why results seem to update instantly when you drag a slider. The trained models are remembered between re-runs, so only the quick calculations are repeated.

Results created by a button disappear on the next change

On the Naive Bayes and Agentic RAG tabs, results appear only on the re-run caused by pressing the button (Classify query or Run retrieval). If you then change anything else on that page, the page re-runs without the button press and the results are replaced by the starting view. Simply press the button again. The VAE, HMM and Evaluation tabs have no such button and always show up-to-date results.

5 · 🧬 VAE Laboratory

Purpose: detect unusual equipment readings. You set four sensor readings with sliders; the model tries to “rebuild” them; if it cannot rebuild them well, the readings are flagged as unusual.

5.1 The idea in plain words

Imagine an apprentice who has looked at thousands of normal sets of readings and has learned to describe each set using just two numbers. From only those two numbers, the apprentice can redraw a full set of four readings. For normal readings the redrawing is very close. For a strange set of readings the apprentice has never seen anything like it, the redrawing is poor, and the difference between what you gave and what came back is large. That difference is the reconstruction error, and a large error means “this looks unusual”.

What do “auto” and “variational” mean?

Autoencoder: a network that learns to copy its input through a narrow bottleneck. Variational: instead of one fixed pair of numbers, the encoder produces a range (a mean and a spread) and the training process samples from it. This makes the “two-number description” smooth and well-behaved. During training the program uses this random sampling. When it judges your readings it uses only the mean (the centre of the range), so the verdict is the same every time for the same sliders.

5.2 Data and training

When the program starts it creates 900 synthetic “normal” readings using bell-shaped random numbers:

FeatureTypical value (mean)Spread (standard deviation)Notes
Temperature55 °C5
Vibration1.00.22Arbitrary vibration units.
Voltage28 V0.8
Packet loss0.6 %0.25Never below 0.
  1. Standardising. Each feature is converted to “how many standard deviations from its typical value” using (value − mean) ÷ spread. This puts temperature (tens) and packet loss (fractions) on a common scale so neither dominates.
  2. Training. The network sees the 900 examples in groups of 64, 120 times over (120 epochs), improving itself with the Adam optimiser at a learning rate of 0.003. Its two goals are: rebuild the input accurately (mean squared error) and keep the two-number description tidy (a small KL divergence penalty, weighted 0.01).
  3. Fixed random seeds. Training always starts from the same random seed (42), so it comes out the same on every start.
  4. Setting the threshold. The program measures the reconstruction error of all 900 normal examples and takes the 95th percentile: the value that 95% of normal examples stay below.
Consequence of the 95th percentile

By design, about 5% of perfectly normal readings will be flagged. The threshold is a trade-off, not a law of nature: a higher percentile would flag fewer normal readings but also catch fewer real problems.

5.8 What the page calculates, step by step

  1. Read the four slider values.
  2. Standardise them with the same means and spreads used in training.
  3. Pass them through the encoder and take the mean latent values (z1, z2).
  4. Pass those through the decoder to get four rebuilt values (still standardised).
  5. Convert the rebuilt values back to original units for the table and bar chart.
  6. Error = the average of the four squared differences between input and rebuilt values (in standardised units).
  7. Verdict: anomaly if Error > Threshold.

5.9 Reading the results correctly

  • Even normal readings have some error. Only two numbers describe four features, and the four training features are generated independently, so the network cannot copy everything exactly. That is why the threshold is not close to zero.
  • “Anomaly” means “unlike the training data”, not “unsafe”. The model has no idea what a real fault looks like; it only knows what its synthetic normal data looked like.
  • Readings far outside the training range (for example 100 °C when normal is 55 ± 5) are many spreads away from anything seen in training and should produce a large error.
  • The model cannot say which feature caused the alarm, but the Input vs Reconstruction chart and table show where the biggest gaps are.
Try it
  1. Press ↻ Reset to Normal Values. The verdict should be normal and the red histogram line should sit among the bars.
  2. Drag Temperature to 100. Watch the needle turn red, the verdict change, and the red line leave the histogram.
  3. Reset, then move only Vibration to 4. Compare the size of the effect with step 2.
  4. Reset, then change two sliders slightly. Observe how the Reconstruction column differs from the Input column.

6 · 📊 Naive Bayes Laboratory

Purpose: sort a typed maintenance sentence into one of three problem categories, and show which manual pages that category favours.

6.1 The idea in plain words

Think of a mail filter that learned that messages containing “prize” and “winner” are usually spam. Naive Bayes does the same with maintenance sentences. From labelled examples it learns which words are typical for each category, then for a new sentence it asks: “Which category would most likely produce these words?” and reports a probability for each category.

Bayes’ theorem and the “naive” assumption

The formula shown on the page is:

P(C | x1, …, xn) ∝ P(C) × ∏ P(xi | C)

  • P(C | words): how likely category C is, given the words seen.
  • P(C): how common the category is in the training examples (the prior). Here all three categories have the same number of examples.
  • P(word | C): how typical each word is for category C.
  • ∝: “proportional to”. The three results are scaled so they add up to 100%.
  • “Naive”: the model pretends every word is independent of the others given the category. This is not true for real language, but it keeps the calculation simple and works surprisingly well.

6.2 Training data and settings

The model learns from 12 short phrases, four per category. The page shows them in a table before you classify anything (columns “Example text” and “Category”).

CategoryTopicTypical words in its examples
preventive_maintenanceRoutine care and inspectiontemperature, cooling, ventilation, airflow, inspect, connectors, schedule
troubleshootingCommunication problemscommunication, intermittent, signal, interference, packet loss, link quality
fault_isolationRestarts and power faultsrestarts, watchdog, resets, unstable power, event logs
  • Turning words into numbers (TF-IDF). Each sentence becomes a list of word weights. Common filler words (“the”, “is”, “and”…) are removed as stop words, and one-word and two-word phrases are both used. A word that is rare across the examples but present in the sentence gets more weight.
  • Smoothing (alpha = 0.5). A small amount is added to every word count so that a word never seen for a category does not force its probability to exactly zero.

6.5 Behaviour notes

  • The probability is not “confidence”. With only 12 training phrases, a very high percentage mostly means your words overlapped strongly with one category’s examples. It is not a calibrated measure of how often the model is right.
  • Unknown words are ignored. Words that never occur in the 12 examples carry no information.
  • No known words at all (for example a sentence about something unrelated) gives roughly 33% for each category, because the model has nothing but the equal priors to go on. The first category alphabetically (fault_isolation) is then shown as the “prediction”, which is a tie-break, not a judgement.
  • Results disappear if you change anything on the page after classifying (see 4.5). Press Classify query again.

7 · 🔗 HMM Laboratory

Purpose: infer the hidden condition of equipment from a series of visible symptoms.

7.1 The idea in plain words

You cannot look inside a machine to see whether it is healthy, degraded or faulty, but you can see symptoms: a high temperature, lost packets, a restart. A Hidden Markov Model (HMM) assumes the machine is always in one of a few hidden states, that it may move between states over time, and that each state tends to show certain symptoms. Given a list of symptoms in time order, the model works out which sequence of hidden states most probably produced them.

An everyday analogy: you are in a windowless room and can only see whether visitors carry umbrellas (the observation). From a week of umbrellas you guess the hidden weather on each day.

7.2 The model’s numbers

An HMM is completely described by three tables of probabilities. In this laboratory they are written by hand for teaching. They were not learned from real equipment histories.

Each row also adds up to 1. For instance, a Fault state shows “Repeated restart” 70% of the time; a Normal state shows “Normal temperature” 75% of the time.

7.3 The Viterbi algorithm in plain words

With three states and four time steps there are already 34 = 81 possible state sequences, and the number explodes for longer series. Viterbi finds the single most probable sequence efficiently:

  1. Step 1. For each state, multiply its starting probability by the probability that it produces the first symptom.
  2. Each later step. For each state, look at every state it could have come from, pick the best predecessor (highest score × transition probability), multiply by the probability of the new symptom, and remember which predecessor won (a “backpointer”).
  3. End. Pick the best state at the last step, then follow the backpointers backwards to recover the whole path.

The program adds logarithms of probabilities instead of multiplying them, because multiplying many small numbers would eventually become too small for a computer to store accurately. The result is the same.

8 · 🔎 Agentic RAG

Purpose: retrieve the most relevant synthetic technical-manual pages for a question, then compare ordinary TF-IDF ranking with a category-aware ranking strategy.

What “Agentic RAG” means here

This laboratory is an educational retrieval prototype. It does not call a large language model to write an answer, and it is not a fully autonomous agent. It retrieves evidence and shows how the ranking was produced. The word “agentic” describes the broader direction of the experiment, not a claim that this prototype plans or acts autonomously.

8.1 The idea in plain words

Retrieval-Augmented Generation (RAG) systems first find relevant source material and then, in a full system, give that material to a language model to help generate an answer. Retrieval quality matters: if the right evidence is not found, a later answer may be incomplete or incorrect.

1 · QuestionYour technical query
→
2 · RetrieveTF-IDF similarity
→
3 · Re-rankOptional category bonus
→
4 · EvidenceRanked document cards

The app contains six short, artificial technical documents. It uses TF-IDF to compare words in your question with words in each document. The Naive Bayes classifier separately predicts a broad query category. In the category-aware strategy, documents whose category matches that prediction receive an additional score bonus.

8.2 How ranking works

Baseline TF-IDF

TF-IDF converts words and short two-word phrases into weighted numerical features. Words that help distinguish one document from another receive more weight than very common words. The query and each document are represented in the same feature space, and cosine similarity scores how closely their vectors point in the same direction. Higher scores mean stronger lexical similarity, not guaranteed factual relevance.

TF-IDF score = cosine similarity(query vector, document vector)

The index uses English stop-word removal, one- and two-word phrases, and sublinear term-frequency scaling. The retrieval index is cached while the Streamlit process is running.

Naive Bayes category-aware ranking

The classifier predicts one of three categories: preventive_maintenance, troubleshooting, or fault_isolation. Category-aware ranking starts with the TF-IDF score and adds a configurable bonus to a document if its category matches the predicted category.

adjusted score = TF-IDF similarity + category bonus (when categories match)

The default bonus is 0.15 in the laboratory. A bonus can promote a document with a matching category, but it cannot guarantee that the document is correct or relevant. The best strategy depends on the question and on the quality of the categories and labels.

9 · 🧪 RAG Evaluation Lab

Purpose: compare baseline TF-IDF retrieval with category-aware re-ranking on a small, fixed set of labelled technical questions.

9.1 Why evaluate retrieval?

A result list can look convincing without containing the document that answers the question. Evaluation compares returned document IDs with a manually prepared set of relevant IDs. It provides a repeatable way to compare strategies, but only to the extent that the questions and relevance labels are appropriate.

Small teaching benchmark

The experiment uses six synthetic documents and six manually labelled questions. It is useful for learning how metrics respond to ranking changes, but it is too small to establish general performance or support production claims.

9.3 Metrics: Recall@3 and Mean Reciprocal Rank

Recall@3

Measures the fraction of labelled relevant documents found in the first three results.

Formula: relevant documents in top 3 ÷ all relevant documents for the question.

If one of two relevant documents appears in the top three, Recall@3 is 1/2 = 0.5.

Mean Reciprocal Rank (MRR)

Rewards finding the first relevant document near the top of the ranking.

Reciprocal rank: 1 ÷ rank of the first relevant result. If the first relevant result is rank 1, the score is 1; at rank 2, it is 0.5; at rank 3, it is about 0.333.

MRR: the average reciprocal rank over all evaluation questions.

Recall@3 considers all labelled relevant documents in the first three positions. MRR focuses on how soon the first relevant result appears. A system can improve one metric without improving the other.

9.6 Reading results carefully

  • A ranking change is not automatically an improvement. The category bonus may move a relevant document upward, leave the list unchanged, or push a relevant document down.
  • Zero bonus is a useful baseline. It removes the category adjustment, so the comparison is driven by the TF-IDF ranking.
  • Do not overgeneralise from six questions. One question can substantially change the average. A larger, diverse and independently labelled evaluation set is needed for stronger conclusions.
  • Review the labels. If more than one document could reasonably answer a question, ensure the ground-truth list reflects that before treating a missed document as a system failure.
  • Metrics do not judge technical safety. They measure agreement with the prepared labels, not whether advice is safe, complete, or suitable for real equipment.

12 · Limitations and responsible interpretation

  • Synthetic evidence: sensor readings, training phrases, model probabilities, document text, and evaluation labels are artificial or hand-authored for education.
  • Not a maintenance authority: the app is not validated against real equipment, service bulletins, engineering limits, or maintenance procedures. Do not use its output to make operational or safety decisions.
  • Small classifier training set: Naive Bayes learns from only a small number of phrases. Unseen vocabulary, ambiguous wording, and topics outside the examples can lead to weak or misleading predictions.
  • Lexical retrieval: TF-IDF relies on word and phrase overlap. It does not understand technical meaning in the way a domain expert or a well-designed semantic retrieval system might.
  • Category-aware re-ranking is heuristic: the bonus may improve or worsen ranking. A category match is not proof that a document answers the question.
  • VAE anomaly detection: the model learns a synthetic representation of normal examples. An anomaly means the input differs from that training pattern; it does not prove a fault or identify its cause.
  • HMM assumptions: the state-transition and symptom-emission probabilities are written for teaching. Real systems may violate the model assumptions and require data-based estimation and validation.
  • Evaluation scope: six questions are too few to provide a stable benchmark. Metrics reflect the supplied labels and corpus, not general retrieval quality.
  • No generated grounded answer: the Agentic RAG tab retrieves evidence and displays scores; it does not call an LLM to synthesize an answer from the retrieved text.
  • Demonstration, not production: the prototype does not provide production monitoring, access control, audit trails, data governance, security hardening, or validated technical workflows.
The right way to use this laboratory

Use it to learn model behaviour, inspect assumptions, compare algorithms, and practise reading metrics. For real technical work, use approved manuals and procedures, validate methods on representative data, and have qualified personnel review conclusions.

13 · Glossary

Anomaly
An input that differs substantially from patterns the model learned as normal. It is not automatically a fault.
Baseline
A reference method used for comparison. Here it means TF-IDF retrieval without a category bonus.
Category-aware re-ranking
Reordering retrieved documents using both their similarity score and whether their category matches the classifier’s predicted category.
Cosine similarity
A measure of the angle between two vectors. In this app it measures how similar the TF-IDF representations of a query and a document are.
Emission probability
In an HMM, the probability of observing a particular symptom given a hidden state.
Evaluation set
A fixed collection of questions and their labelled relevant documents used to compare retrieval strategies.
Feature
A measurable input variable used by a model, such as temperature or a numerical representation of a word.
Ground truth
The prepared reference answer used to judge a model output. In this app, it is a manually assigned list of relevant document IDs.
Hidden state
A condition that the HMM does not observe directly but attempts to infer from visible symptoms.
HMM (Hidden Markov Model)
A probabilistic sequence model defined by starting-state probabilities, transition probabilities, and emission probabilities.
Inference
Using a trained or specified model to produce a prediction or score for an input.
Mean Reciprocal Rank (MRR)
The average of the reciprocal rank of the first relevant result across evaluation questions. Higher is better when the relevance labels are appropriate.
Naive Bayes
A probabilistic classifier based on Bayes’ theorem and a simplifying conditional-independence assumption about features.
Recall@3
The fraction of labelled relevant documents that appear among the first three retrieved results.
Reconstruction
The output produced when a model attempts to rebuild its input. The VAE compares this output with the original readings.
Reconstruction error
A numerical measure of the difference between an input and its reconstruction. In this VAE lab, it is the mean squared difference in standardised feature space.
Retrieval
Finding and ranking documents that may be useful for answering a question.
RAG (Retrieval-Augmented Generation)
A system pattern in which retrieved source material is supplied to a generative model to support an answer. This prototype demonstrates retrieval, not answer generation.
TF-IDF
Term Frequency–Inverse Document Frequency, a method for weighting words according to their frequency in a text and how distinctive they are across a collection.
Transition probability
In an HMM, the probability of moving from one hidden state to another at the next time step.
Training data
Examples used to fit a model or define its behaviour. The app’s training data is small and synthetic.
VAE (Variational Autoencoder)
A neural network that learns a compressed latent representation and reconstructs inputs. This lab uses reconstruction error as a teaching example of anomaly detection.
Viterbi algorithm
A dynamic-programming algorithm that finds the most probable sequence of hidden states for a sequence of observations under an HMM.
